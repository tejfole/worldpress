Rendszerterv – Ubuntu Server LTS alapú egygépes kisvállalati szerver

Verzió: v4
Dátum: 2026-06-09
Cél: WordPress + saját PHP/Java alkalmazások + MariaDB + belső fájlmegosztás + backup + Microsoft 365 / Entra integráció

Fontos frissítés: az alaplap nem támogat hardveres RAID-et, ezért a terv Linux szoftveres RAID-re épül: mdadm + opcionális LVM + ext4. Hardveres/alaplapi RAID nem szükséges.

1. Áttekintés

Ez a rendszerterv egy egygépes, kisvállalati szerver kialakítását írja le, amely egyszerre szolgál ki:

  • publikus webes szolgáltatásokat
  • belső hálózati fájlmegosztást
  • adatbázis alapú alkalmazásokat
  • helyi és külső backup folyamatokat
  • Microsoft 365 / Entra ID integrációt

A cél egy egyszerűen üzemeltethető, biztonságos, jól tagolt infrastruktúra.

4. Gyakorlati architektúra

A szerver egy gépen futtatja az alábbi szerepköröket:

  • Publikus szolgáltatások: WordPress, saját PHP appok, saját Java appok Apache reverse proxy mögött
  • Belső szolgáltatások: SSH admin, Samba, backup műveletek, opcionális belső admin végpontok
  • Adatszolgáltatások: MariaDB, fájltárolás, mentési tárterület
  • Integráció: Entra ID login, Microsoft Graph alapú email küldés

5. Tárolási terv

Véglegesített gyakorlati modell:

  • md0 – rendszer: SSD1 + SSD2 → mdadm RAID1
  • md1 – adat: SSD3 + SSD4 → mdadm RAID1

Mindkét tömb kb. 232 GiB hasznos kapacitást ad.

7. Hálózati terv

Példa interfésznevek:

  • enp1s0 = publikus
  • enp2s0 = belső

🟩 Publikus NIC

  • IP: szolgáltatótól kapott statikus publikus IP
  • gateway: szolgáltatói gateway
  • DNS: pl. 1.1.1.1, 8.8.8.8

🟦 Belső NIC

  • IP: 192.168.10.10/24
  • gateway: nincs

Szabály: default route csak a publikus interfészen legyen. SSH és Samba csak a belső IP-ről legyen elérhető.

Netplan minta

network:
  version: 2
  renderer: networkd

  ethernets:
    enp1s0:
      dhcp4: false
      addresses:
        - 203.0.113.10/24
      routes:
        - to: default
          via: 203.0.113.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8

    enp2s0:
      dhcp4: false
      addresses:
        - 192.168.10.10/24

  • reverse proxy

  • wordpress

  • app2

Javasolt userek:

  • wp-www
  • app1-www
  • app2-www

🟩 Java appok

  • service userek: app1svc, app2svc
  • localhost portok: 127.0.0.1:8081, 127.0.0.1:8082
  • Apache proxy mögött

🟧 MariaDB

  • csak 127.0.0.1
  • külön DB user alkalmazásonként

10. Apache vhost modell

  • www.domain.hu → WordPress
  • app1.domain.hu → PHP app1
  • app2.domain.hu → PHP app2
  • api.domain.hu → Java app1 proxy
  • admin.domain.local → opcionális belső admin

Elv: minden site külön vhost, külön log, külön document root, külön PHP pool vagy proxy target, HTTPS mindenen.

11. MariaDB terv

Adatbázisok:

  • wordpress_db
  • app1_db
  • app2_db

Userek:

  • wordpress_user
  • app1_user
  • app2_user

Beállítások: bind-address = 127.0.0.1, karakterkészlet utf8mb4, root távoli login tiltva.

Mentés: napi SQL dump, lokális retention legalább 7–14 nap.

12. Samba terv

Share-ek:

  • common – általános irodai fájlok
  • projects – projektdokumentumok
  • exchange – ideiglenes csereanyagok

Könyvtárak: /srv/share/common, /srv/share/projects, /srv/share/exchange

Jogosultsági csoportok: office, projects, opcionálisan management

Fontos szabály: WordPress vagy app source ne legyen általános SMB share.

13. WordPress + Entra + Graph

  • WordPress külön könyvtárban, külön adatbázissal, külön PHP poollal
  • Entra login: WPO365 vagy hasonló plugin
  • Graph mail: contact form, jelszó-visszaállítás, admin riasztások
  • nincs helyi SMTP szerver

Külön figyelni kell: secret kezelés, plugin update kompatibilitás, token renewal.

14. Backup terv

Mentendő elemek:

  • /etc
  • /srv/www
  • /srv/data
  • /srv/share
  • /opt/apps
  • MariaDB dumpok
  • Apache configok
  • PHP-FPM pool configok
  • Samba config
  • systemd unitok

Cél: /srv/backup/daily

Verziózott mentés: restic repository lokális staginggel, később külső célra szinkronizálva.

Ütemezés:

  • naponta: DB dump, config mentés, fájlmentés
  • hetente: teljes backup ellenőrzés
  • havonta: restore teszt

15. Biztonsági baseline

🟥 SSH

  • csak belső NIC
  • root tiltva
  • password auth tiltva
  • key auth

🟥 Tűzfal

Publikus: allow 80, allow 443, minden más tiltva.

Belső: allow 22/445/139 a 192.168.10.0/24 hálózatból.

🟥 Egyéb

  • MariaDB localhost only
  • Samba: interfaces = belső NIC, bind interfaces only = yes
  • Apache/PHP: server tokens off, directory listing off, szükségtelen modulok off
