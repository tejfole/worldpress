Rendszerterv – Ubuntu Server LTS alapú egygépes kisvállalati szerver

Verzió: v2
Dátum: 2026-06-09
Cél: WordPress + saját PHP/Java alkalmazások + MariaDB + belső fájlmegosztás + backup + Microsoft 365 / Entra integráció

Fontos frissítés: az alaplap nem támogat hardveres RAID-et, ezért a terv Linux szoftveres RAID-re épül: mdadm + opcionális LVM + ext4. Hardveres/alaplapi RAID nem szükséges.

1. Áttekintés

Ez a rendszerterv egy egygépes, kisvállalati szerver kialakítását írja le, amely egyszerre szolgál ki:

  • publikus webes szolgáltatásokat
  • belső hálózati fájlmegosztást
  • adatbázis alapú alkalmazásokat
  • helyi és külső backup folyamatokat
  • Microsoft 365 / Entra ID integrációt

A cél egy egyszerűen üzemeltethető, biztonságos, jól tagolt infrastruktúra.

5. Hálózati terv

🟩 Publikus interfész – NIC1

Feladata:

  • publikus IP
  • alapértelmezett gateway
  • webes szolgáltatások kiszolgálása

Nyitott portok: 80/tcp, 443/tcp

🟦 Belső interfész – NIC2

Feladata:

  • SSH admin
  • Samba
  • backup forgalom
  • belső szolgáltatások

Javasolt portok: 22/tcp, 445/tcp, 139/tcp

Hálózati alapelv:

  • SSH csak belső hálózaton
  • Samba csak belső hálózaton
  • MariaDB csak localhoston
  • Java appok ne legyenek közvetlenül publikusak
  • Apache legyen az egyetlen publikus belépési pont

6. Szoftver stack

Operációs rendszer

  • Ubuntu Server 24.04 LTS (konzervatív, kiforrott választás)
  • alternatívaként: Ubuntu Server 26.04 LTS új telepítéshez

🟩 Web és alkalmazás

  • Apache2
  • PHP-FPM
  • PHP modulok: php-mysql, php-xml, php-curl, php-gd, php-mbstring, php-zip, php-intl, php-bcmath, php-imagick (opcionális)
  • Certbot / ACME
  • mod_ssl, mod_headers, mod_rewrite, mod_proxy, mod_proxy_http, mod_proxy_fcgi

🟧 Adatbázis

  • MariaDB Server
  • MariaDB Client

🟩 Java futtatókörnyezet

  • OpenJDK 21 LTS (ha az alkalmazások támogatják)
  • systemd service-ek

🟦 Fájlmegosztás

  • Samba

🟥 Biztonság és üzemeltetés

  • openssh-server
  • chrony
  • unattended-upgrades
  • rsync
  • logrotate
  • fail2ban
  • ufw vagy nftables

🟧 Backup

  • restic vagy borgbackup
  • mariadb-dump
  • rclone (ha külső mentés kell)

7. Szolgáltatási architektúra

🟩 Apache

  • HTTP/HTTPS végpontok kezelése
  • virtual hostok
  • TLS terminálás
  • PHP-FPM kiszolgálás
  • reverse proxy Java appok elé

🟩 PHP-FPM

Ajánlott külön poolok:

  • wordpress

  • app2

🟩 WordPress

  • helye: /srv/www/wordpress

  • külön MariaDB adatbázis

  • külön mentési szabály

🟩 Saját PHP alkalmazások

  • /srv/www/app1
  • /srv/www/app2

🟩 Java alkalmazások

  • /opt/apps/app1
  • /opt/apps/app2
  • systemd service
  • localhost portok: 127.0.0.1:8081, 127.0.0.1:8082
  • Apache reverse proxy mögött

8. Adatbázis terv

🟧 MariaDB alapelvek

  • csak localhost elérés
  • külön adatbázis minden alkalmazáshoz
  • külön felhasználó minden alkalmazáshoz
  • root távoli belépés tiltva
  • karakterkészlet: utf8mb4

Javasolt adatbázisok: wordpress_db, app1_db, app2_db

Erőforrás-javaslat: 16 GB RAM mellett induló cél: MariaDB 2–4 GB memóriahasználat

9. Microsoft 365 / Entra integráció

🟪 Azonosítás

  • Entra ID alapú bejelentkezés WordPresshez
  • WPO365 vagy kompatibilis plugin

🟪 Email küldés

  • Microsoft Graph API használata
  • nincs helyi mail szerver
  • nincs php mail()
  • nincs publikus SMTP szolgáltatás

Szükséges elemek:

  • Entra app registration
  • tenant ID
  • client ID
  • client secret vagy certificate
  • redirect URL-ek
  • Graph API engedélyek

A WordPress csak küldésre használja a Microsoft 365 környezetet. A teljes levelezés az Office 365-ben marad.

10. Samba és fájlmegosztás

🟦 Szerep

Javasolt share-ek:

  • common

  • DB könyvtár ne legyen share-ként kitéve

11. Backup stratégia

🟧 Lokális backup

Napi mentés:

  • MariaDB dump
  • /etc
  • Apache konfigurációk
  • PHP-FPM konfigurációk
  • WordPress fájlok
  • alkalmazáskönyvtárak
  • systemd unitok

Célkönyvtár: /srv/backup/daily

🟧 Verziózott backup

Ajánlott eszköz: restic

Cél:

  • lokális staging
  • külső NAS
  • S3 kompatibilis tároló

Minimum szabály:

  • napi mentés
  • heti ellenőrzés
  • havi restore teszt
  • legalább 1 külső/offsite másolat
