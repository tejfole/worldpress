Rendszerterv – Ubuntu Server 26.04 LTS alapú egygépes kisvállalati szerver

Verzió: v5.1
Dátum: 2026-06-09
Cél: WordPress + saját PHP/Java alkalmazások + MariaDB + belső fájlmegosztás + backup + Microsoft 365 / Entra integráció + GNOME + Webmin + phpMyAdmin

Fontos: az alaplap nem támogat hardveres RAID-et, ezért a terv Linux szoftveres RAID-re épül: mdadm + opcionális LVM + ext4. Hardveres/alaplapi RAID nem szükséges.

1. Áttekintés

Ez a rendszerterv egy egygépes, kisvállalati szerver kialakítását írja le, amely egyszerre szolgál ki:

  • publikus webes szolgáltatásokat
  • belső hálózati fájlmegosztást
  • adatbázis alapú alkalmazásokat
  • helyi és külső backup folyamatokat
  • Microsoft 365 / Entra ID integrációt
  • grafikus adminisztrációt GNOME környezettel
  • belső adminisztrációs felületeket Webminnel és phpMyAdminnal

5. Tárolási terv

  • md0 – rendszer: SSD1 + SSD2 → mdadm RAID1
  • md1 – adat: SSD3 + SSD4 → mdadm RAID1

Mindkét tömb kb. 232 GiB hasznos kapacitást ad.

🟩 Rendszer tömb – md0

CsatolásMéretCél

/optmaradékJava appok, egyedi telepítések

🟧 Adat tömb – md1

CsatolásMéretCél
/srvteljes tömbwebhelyek, adatok, Samba, backup staging

Technológiai javaslat: mdadm + opcionális LVM + ext4

Swap: külön partíció helyett 8 GB swapfile

Storage telepítési minta

Az eszköznevek (/dev/sda, /dev/sdb, stb.) telepítésenként eltérhetnek. Mielőtt bármit létrehozol vagy törölsz, ellenőrizd a valós lemezkiosztást: lsblk -o NAME,SIZE,TYPE,MODEL. 
# csomagok
sudo apt update
sudo apt install -y mdadm lvm2

# lemezek ellenőrzése
lsblk -o NAME,SIZE,TYPE,MODEL

# példa tömbök létrehozása
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sda /dev/sdb
sudo mdadm --create /dev/md1 --level=1 --raid-devices=2 /dev/sdc /dev/sdd

# fájlrendszerek
sudo mkfs.ext4 /dev/md0
sudo mkfs.ext4 /dev/md1

# mountpontok
sudo mkdir -p /mnt/md0 /mnt/md1
sudo mount /dev/md0 /mnt/md0
sudo mount /dev/md1 /mnt/md1

# tartós mdadm config
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u

11. Apache vhost modell

  • www.domain.hu → WordPress
  • app1.domain.hu → PHP app1
  • app2.domain.hu → PHP app2
  • api.domain.hu → Java app1 proxy
  • admin.domain.local → belső admin, phpMyAdmin opcionálisan itt

Elv: minden site külön vhost, külön log, külön document root, külön PHP pool vagy proxy target, HTTPS mindenen.

# szükséges modulok
sudo a2enmod ssl headers rewrite proxy proxy_http proxy_fcgi setenvif auth_basic
sudo systemctl restart apache2

Vhost minta – WordPress

<VirtualHost *:80>
    ServerName www.domain.hu
    DocumentRoot /srv/www/wordpress

    ErrorLog ${APACHE_LOG_DIR}/wordpress-error.log
    CustomLog ${APACHE_LOG_DIR}/wordpress-access.log combined

    <Directory /srv/www/wordpress>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

Vhost minta – Java app proxy

<VirtualHost *:80>
    ServerName api.domain.hu

    ProxyPreserveHost On
    ProxyPass / http://127.0.0.1:8081/
    ProxyPassReverse / http://127.0.0.1:8081/

    ErrorLog ${APACHE_LOG_DIR}/api-error.log
    CustomLog ${APACHE_LOG_DIR}/api-access.log combined
</VirtualHost>

Vhost minta – phpMyAdmin belső elérésre

<VirtualHost *:80>
    ServerName admin.domain.local

    Alias /phpmyadmin /usr/share/phpmyadmin

    <Directory /usr/share/phpmyadmin>
        Require ip 10.1.0.0/16
        AllowOverride None
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/phpmyadmin-error.log
    CustomLog ${APACHE_LOG_DIR}/phpmyadmin-access.log combined
</VirtualHost>
